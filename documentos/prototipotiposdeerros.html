Code Smells — Tipos de Erros

Sintomas de que algo está errado no design ou implementação, prejudicando manutenção, testabilidade e evolução do sistema.

Visão Geral

Problema Impacto Principal Severidade
God Class Manutenibilidade e rigidez do design Critical
Código Duplicado Custo de manutenção e risco de bugs High
Callback Hell Legibilidade e controle de fluxo Medium
Variáveis Abreviadas Compreensão imediata do negócio Low

Explicação Detalhada

God Class Classe Deus
Critical
Classe que "sabe demais" ou "faz demais". Viola o Princípio da Responsabilidade Única (SRP) do SOLID. Classe central com milhares de linhas, conectada a quase todas as outras partes do software.
  • Acoplamento Alto: qualquer mudança pode quebrar o sistema inteiro.
  • Baixa Coesão: processa pagamento, envia e-mail e valida CPF na mesma classe.
Por que é Critical É o erro mais estrutural e perigoso. Cria um ponto único de falha e alto acoplamento em todo o sistema. Em ecossistemas como Spring Boot, trava a evolução da aplicação, impede testes unitários eficazes e torna qualquer refatoração futura um pesadelo de regressão.
Solução Refatorar dividindo responsabilidades em classes menores e especializadas (serviços, utilitários, entidades).
Código Duplicado Duplicate Code — DRY Violation
High
O famoso "Ctrl+C, Ctrl+V". Ocorre quando a mesma lógica aparece em dois ou mais lugares do sistema. Viola o princípio DRY (Don't Repeat Yourself). Se precisar corrigir um bug, terá que lembrar de todos os lugares onde copiou aquele código. Se esquecer um, terá comportamentos inconsistentes.
Por que é High O impacto é direto na manutenção. Se uma regra de negócio muda ou um bug é encontrado na lógica duplicada, você terá que corrigi-lo em múltiplos lugares. A chance de esquecer um ponto e gerar inconsistência de dados — especialmente em transações de banco de dados — é altíssima.
Solução Extração de método ou criação de uma classe utilitária/serviço que centralize essa lógica.
Callback Hell Inferno de Callbacks
Medium
Ocorre principalmente em linguagens assíncronas como JavaScript. Acontece quando várias funções assíncronas são aninhadas umas dentro das outras, criando uma estrutura de código em formato de "pirâmide" que se move horizontalmente para a direita. Torna o código extremamente difícil de ler, debugar e tratar erros, já que o fluxo lógico fica fragmentado.
Por que é Medium Embora torne o código difícil de ler e manter, o impacto costuma ficar restrito àquela camada específica de execução assíncrona. Em Java moderno (usando CompletableFuture ou Project Reactor) é facilmente mitigado, mas ainda prejudica a rastreabilidade de erros com Stack Traces complexos.
Solução Utilizar Promises, async/await ou modularizar as funções em arquivos separados.
Variáveis Abreviadas Obscurity
Low
É a prática de nomear variáveis com apenas uma letra ou siglas que não deixam claro o propósito do dado. Ex: int d = 10 em vez de int diasParaVencimento = 10. O código é lido muito mais vezes do que é escrito. Variáveis como usr, pts ou temp obrigam o desenvolvedor a gastar energia mental tentando lembrar o que aquele valor representa no contexto.

Exceção: variáveis de controle de loop muito curtos, como o famoso i em um for.
Por que é Low É um problema de legibilidade e "limpeza" (Clean Code). Embora dificulte o entendimento para novos desenvolvedores e aumente a carga cognitiva, não costuma causar falhas de execução ou impedir a escalabilidade do sistema por si só. É o mais simples de resolver com ferramentas de refatoração da IDE.
Solução Adotar Clean Code. Nomes devem ser descritivos e pronunciáveis.

Visão de Arquitetura — Outras Categorias

Bloatheads — Inchadores

God Class Classe central que faz tudo — ponto único de falha.
Long Method Método com muitas linhas. Se precisa de comentário para explicar uma parte, essa parte deveria ser um método próprio.
Data Clumps Grupos de variáveis que quase sempre aparecem juntas (inicio_periodo, fim_periodo) deveriam ser uma classe própria.

Obstrucionistas de Mudança

Divergent Change Você precisa alterar uma mesma classe por muitos motivos diferentes — indica falta de coesão.
Shotgun Surgery Oposto do Divergent Change: uma única alteração exige pequenos ajustes em várias classes diferentes.

Dispensáveis

Lazy Class Classe que não faz o suficiente para justificar sua existência.
Dead Code Código que nunca é executado: funções órfãs, variáveis não utilizadas.
Speculative Generality "Vou deixar isso pronto caso a gente precise no futuro" — mas nunca é usado.

Acopladores

Feature Envy Método de uma classe mais interessado nos dados de outra do que nos seus próprios.
Inappropriate Intimacy Uma classe usa campos ou métodos privados de outra de forma excessiva.

Tabela de Comparação de Severidade

Code Smell Classificação Por que?
Shotgun Surgery Critical Torna a manutenção extremamente lenta e propensa a erros.
Feature Envy High Indica que a lógica de negócio está no lugar errado.
Long Method Medium Dificulta a leitura e os testes unitários.
Dead Code Low Aumenta o tamanho do projeto, mas não afeta a execução.
